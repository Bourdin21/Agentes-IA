### 2026-08-21 - orquestador (bug reportado por el owner probando en producción, fuera de ciclo formal)
- Etapa: Implementación (hotfix, mismo criterio de severidad que ELV-001 — sin pasar por Análisis/Diseño/Arquitectura/Presupuesto)
- Cambio: **ELV-002 aplicado** (`AlquilerService.UpdateAsync` ahora valida `FechaDevolucion >= Fecha`, igual que Create). **Bug nuevo encontrado y corregido (sin id catalogado todavía, sugerido ELV-003):** al crear un alquiler para Máquina #161 (NroInterno, Id real 391) el sistema rechazaba por "máquina ya alquilada", pero el Alquiler bloqueante (#421, cliente ACEAPP, desde 01/02/2024, sin finalizar) no aparecía en el listado de Alquileres. Causa raíz confirmada con SQL directo: `ClienteId`/`MaquinaId` en `Alquiler` son FKs requeridas (int no-nullable) sin configuración Fluent API explícita — EF Core traduce `Include(a => a.Cliente)`/`Include(a => a.Maquina)` + el filtro global de soft-delete como INNER JOIN, así que un Alquiler activo desaparece por completo de listados/detalle si su Cliente o Máquina fue dado de baja después. Confirmado en producción: **101 Alquileres con Cliente borrado + 50 con Máquina borrada, invisibles** (mismo patrón afecta a `Contratos→Cliente`, 2 filas; `Incidencias`/`PedidosTecnico` no tienen filas afectadas hoy). Se reescribieron `GetDataTableAsync`, `GetByIdAsync`, `GetDetailsAsync` y `BuscarAlquilerBloqueanteAsync` de `AlquilerService.cs` para dejar de usar `Include()` sobre Cliente/Máquina y resolverlos con lookups manuales (`IgnoreQueryFilters()`), que siempre preservan la fila del Alquiler y muestran "(de baja)" en vez de ocultarlo. También se actualizó dashboard (`HomeController`/`DashboardViewModel`/`Home/Index.cshtml`): se sacaron 4 cards (Clientes, Máquinas, Incidencias resueltas del mes, Pedidos Técnico pendientes) y 4 accesos rápidos (Nuevo Alquiler, Nuevo Cliente, Pedido Técnico, Nueva Máquina); se agregaron 3 accesos rápidos (Cuentas Propias, CC Clientes, CC Proveedores), ocultos para rol Técnico igual que Finanzas en el sidebar.
