### 2026-08-20 — orquestador (CR-52: bug crítico — AFIP no podía emitir ningún comprobante real, deployado a producción)
- Etapa: Fix de bug crítico en producción, reportado directamente por el cliente al intentar facturar la Venta #676 (Comprobante AFIP #304).
- Causa raíz: `AfipService.FirmarCms` pasaba `AfipSettings.CertificadoPath` (ruta relativa "Certificados/marihogarprod.p12") directo a `X509CertificateLoader.LoadPkcs12FromFile`, que la resuelve contra el directorio de trabajo actual del proceso — no necesariamente el ContentRootPath del sitio. Cualquier discrepancia produce "The system cannot find the file specified" aunque el certificado exista en el lugar correcto. - Fix: `AfipService` ahora inyecta `IWebHostEnvironment` y resuelve `CertificadoPath` siempre contra `ContentRootPath` (mismo patrón que `LocalFileStorageService`), más un chequeo temprano con mensaje claro si el archivo no aparece en la ruta resuelta.

- Motivo: Bug crítico reportado por el cliente, bloqueaba la facturación electrónica real.

### 2026-08-20/21 — orquestador (CR-52, 2do hallazgo real: EphemeralKeySet para el certificado AFIP)
- Etapa: Continuación del fix de bug crítico — el 1er fix (ContentRootPath) no resolvió el problema. Verificado directo contra producción (no solo por lo reportado por el cliente): `ComprobanteAfip.DetalleError` del comprobante #303 y #304 seguía siendo idéntico ("The system cannot find the file specified") después de 2 deploys del 1er fix.
- Diagnóstico: un redeploy posterior confirmó por diff de `msdeploy` que los binarios del 1er fix ya estaban correctamente en el servidor (0 cambios en los .dll) — descartando que el problema fuera el deploy en sí. Causa real identificada: `X509CertificateLoader.LoadPkcs12FromFile` sin flags usa `X509KeyStorageFlags.DefaultKeySet`, que en Windows intenta persistir la clave privada en el perfil de usuario del proceso — si el Application Pool de IIS no tiene "Load User Profile" habilitado (común en hosting compartido tipo SmarterASP.NET/site4now), esa carpeta no existe y CryptoAPI devuelve el mismo error genérico de archivo no encontrado, aunque el .p12 esté presente y en la ruta correcta.
- Fix: se agrega `X509KeyStorageFlags.EphemeralKeySet` al cargar el certificado — la clave privada queda solo en memoria durante la firma CMS, nunca se persiste en disco, sin depender del perfil de Windows del Application Pool.
- Motivo: Continuación de CR-52, bug crítico bloqueando la facturación electrónica real.
- Impacto en capas: Infrastructure (`AfipService.cs`). Sin migración EF.
- Riesgos/supuestos: Sin smoke test — recomendado que el cliente reintente la emisión del Comprobante #304 para confirmar el fix contra AFIP real. Backup de producción previo (15.837.135 bytes, trailer confirmado). ### 2026-08-21 — orquestador (CR-52, causa final identificada: falta habilitar Punto de Venta tipo Web Service en AFIP)
- Etapa: Continuación del diagnóstico — con el certificado ya cargando/firmando correctamente (MachineKeySet), el reintento del Comprobante #304 devolvió un error REAL de AFIP (no más un error local): "11002 - El punto de venta no se encuentra habilitado a usar en el presente WS. - Diagnóstico definitivo: se agregó un método puntual `AfipService.ConsultarPuntosVentaAsync()` (no expuesto en `IAfipService`/UI, herramienta de soporte) y se ejecutó un runner standalone contra AFIP Producción real, usando el certificado local — AFIP respondió `Err 602 "Sin Resultados"` para `FEParamGetPtosVenta`: **no hay ningún punto de venta habilitado para WSFE (Web Service) en este CUIT**. Se armó y entregó `docs/marihogar/guia-habilitar-punto-venta-afip.md` con el paso a paso para que el cliente lo resuelva de su lado. Una vez que el cliente tenga el número de punto de venta habilitado, falta actualizar `Afip:PuntoVenta` en `appsettings.Production.json` (si difiere de 4) y volver a probar.
- Motivo: Cierre del diagnóstico de CR-52 — el certificado/firma/conexión con AFIP ya están confirmados funcionando de punta a punta.

- Fix real aplicado: `builder.Services.AddDataProtection().PersistKeysToFileSystem(new DirectoryInfo(Path.Combine(ContentRootPath, "DataProtection-Keys"))).SetApplicationName("MariHogar")` en `Program.cs`. Carpeta `DataProtection-Keys/` gitignorada (mismo patrón que `Certificados/`) y excluida del sync de `deploy-prod.ps1` vía `-skip:objectName=dirPath,absolutePath=DataProtection-Keys` (mismo mecanismo ya usado para no perder el certificado AFIP en cada deploy). Sin cifrado adicional de las claves en disco (sin DPAPI de máquina confiable en este hosting, mismo hallazgo que motivó `X509KeyStorageFlags.MachineKeySet` en CR-52) — mismo nivel de exposición que `appsettings.Production.json`, ya sin cifrar en el mismo servidor.
- Motivo: pedido del cliente sobre un síntoma real (invalidación de sesión/tokens), pero apuntando a la solución de la generación de ASP.NET equivocada — se corrigió el mecanismo correcto para esta app.
- Impacto en capas: Web (`Program.cs`, `.gitignore`), Infraestructura de deploy (`scripts/deploy-prod.ps1`). Sin migración EF.
